1. POOL NO LONGER RE-PACKS (§9.3)
   Slots are keyed on the tile's fixed index in the level's pool, so consumption cannot
   enter the position calculation at all. Ghosts render stroke-only in the vacated slot
   and cannot collide with a live tile, because no live tile can ever be there.

   PROVEN, not eyeballed. Pixel diff of the surviving tiles between the FRESH board and
   the board after two commits (four tiles spent):
     tile 7, slot 4:  max channel difference 0   (0 of 20172 samples differ)
     tile 8, slot 5:  max channel difference 0   (0 of 20172 samples differ)

   Ghosts are now derived from tile.consumed rather than from a list of bounds recorded
   when a shatter fired. The old list was redundant and could not survive a reload — a
   level resumed mid-play had no shatter history, so it would have shown no ghosts.

   Bounds: MIN 46 is the tap floor (~43 CSS px on a 393px phone, at the platform
   minimum). MAX 92 is where a tile stops reading as a game piece and starts reading as
   a menu button. The ladder uses 55-92 of that 46-92 range.

   SOLVED, not tabulated. The size is the largest that still fits the screen, found by
   searching down from MAX. A formula from tile count would need re-tuning whenever a
   band changed height and would silently overflow when wrong; a search cannot overflow,
   because fitting is the search condition. The inverse relationship §9.2 asks for falls
   out as a consequence — more tiles need more rows, so they run out of room sooner.

   TWO THINGS THE TESTS CAUGHT, both real:
   a) 13 tiles gridded as 4/4/4/1. A lone tile on the last row reads as a mistake, so
      the search now requires a balanced grid and drops a size to get 5/5/3.
   b) That balance rule then broke the inverse scaling: 13 tiles landed at 72 and 14 at
      80, so crossing that boundary made tiles GROW as the board got harder — inverting
      the signal §9.2 is buying. Size is now forced non-increasing in tile count. Costs
      one 14-tile board a couple of pixels.

3. ANCHORED LOW
   The column now ends a constant 12px from the bottom and all slack sits above the lane.
   World 1 was ~200px above and ~190px below; it is now 134px above and 12px below, and
   most of the old gap went into the tokens rather than being redistributed.

4. OPERATOR COLOUR — grey is the DIM STATE, and it is correct.
   The 0x22333b recolour did reach the binary operators. Shot 06 stages a 4 and all four
   render dark navy.
   Binary operators are unusable until a number is staged, so on a fresh board they are
   dim — §3.5's rule that bold-active is always paired with dim-inactive.
   sqrt is exempt because it is genuinely available: a unary transform is a legal move
   with nothing staged, so it is never in the "waiting for a number" state. It is lit
   because it can be tapped right now, which is exactly what lit is supposed to mean.
   Nothing to fix.
