RETRY PATH — THE NUMBER
  1 FRAME. Five measured runs on 1-06 played to a genuine failure:
    frames 1, 1, 1, 1, 1     ms 29.5 / 37.5 / 38.3 / 34.9 / 41.7
  The board is playable in the SAME SYNCHRONOUS TICK as the restart input —
  measureRetry() checks phase and targetIndex immediately after send() returns,
  before any frame boundary, and it is already playing at target 0 with all 6
  tiles restored. The 1 frame is simply the next paint.
  Screens between failure and playable: 0. Modals: 0. Transitions: 0.
  The ms figure is the animation-frame interval under the automation harness,
  not a 60fps steady state — the frame count is the honest number.

THE REGISTER — what was deliberately NOT built
  No screen shake, anywhere. The closest thing in the game is the equation row
  resisting an illegal commit, and it is confined to the row: the pool and the
  lane do not move, so nothing reads as an impact on the whole board.
  No confetti, no sparkle, no cartoon squash. The settle curve overshoots about
  3% where the stock back-out constant overshoots 10% — that difference is the
  difference between a Scrabble tile and a beach ball, and it is asserted in a
  test so it cannot drift.

BUILT
  src/renderer/tween.ts — one clock, one set of curves, one timing table. Every
  effect reads from it. lift 150 / place 260 / return 210 / hitStop 80 /
  laneAdvance 340 / resist 380 / rewrite 340 / starGap 190.
  Effects hold PROGRESS, never display objects, because the board is rebuilt
  every frame — draw() asks them where things are. That is why they compose.

TWO THINGS THAT ARE NOT PURE FEEL — flagging both
  1. DIRECTOR CHANGED. A refused commit no longer empties the equation row.
     9.5's table says "tiles stay put", and there was nothing to leave standing:
     the Director cleared all three slots on a wrong answer. It also charged
     three taps to re-enter a guess, for something 2 step 4 explicitly says is
     not a failure state. Now the equation stands and the player can fix just
     the operator. One test asserted the old behaviour and was updated; a new
     test covers the correction path.
  2. TOKEN PARAMETER ADDED. TokenStyle gained `elevation`, which scales the
     EXISTING drop shadow and touches no colour or shape. 9.5 asks for "shadow
     deepens" on lift, and the shadow is most of what makes a lift read as
     height rather than as the tile just getting bigger.

DEFECT FOUND BY THE INSTRUMENTATION
  After a successful commit the two spent tiles were flying home to the pool AND
  shattering toward the lane at the same time — a successful commit clears the
  slots, which looks identical to a return. Only visible because feel() reported
  two toPool flights that should not exist. Fixed: a consumed tile has nowhere
  to return to. Re-verified at 0 spurious returns.

ALSO
  setEffectSpeed(0) now PAUSES rather than clamping to 0.05. It is the only way
  to photograph a frame honestly — a screenshot round-trip is slower than any
  effect here, so at any non-zero speed the shutter races the animation. It was
  needed within ten minutes of starting the verification.
