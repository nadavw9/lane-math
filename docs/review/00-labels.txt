2. PIXI PRODUCTION BUILD — THE PREMISE WAS WRONG, AND IT WAS MY ERROR

   There is no production Pixi build to select. Pixi 8.19 publishes ONE
   artefact: exports for "." are a single lib/index.mjs with no production or
   development condition. And the deprecation helper is not gated at all —
   NODE_ENV appears nowhere in pixi.js/lib. So those strings are unconditional
   code that ships in every Pixi 8 build, not evidence of a dev bundle.

   Last session I inferred a dev build from those strings. That inference was

4. DEVICE CHECKLIST — docs/device-checklist.md, ready to run in one pass

   Seven items, each with the exact commands and an explicit pass condition, so
   it runs start to finish once adb sees the phone. No AVD needed; it targets
   the signed APK already built.

   The two most likely failures, called out in the document:
     - SAFE AREA AT THE BOTTOM. The column anchors 12px from the bottom, which
       is where the gesture bar lives, and the status band there carries
       restart, the mode selector and the map button — interactive, not
       decorative. The fix if it fails is a safe-area inset, NOT nudging the
       12px, which is derived and would put a magic number back.
     - BRIGHTNESS UNDER SUNLIGHT. Measured margins are 3.46-4.05:1 against a
       3:1 floor, tuned on a desktop monitor. Thin headroom for a phone panel.
       If it fails the fix is the background, not the threshold (9.1).

   Also covered: install, portrait lock through a forced rotation, tap latency
   against the 0.5ms harness baseline WITH a diagnostics check that flights
   stays at 1 under real thermal conditions, all three AdMob outcomes including
   aeroplane-mode no-fill, and a screenshot per world.
